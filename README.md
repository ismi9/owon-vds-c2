# owon-vds-c2

Реверс-інжиніринг протоколу зв'язку портативного осцилографа **OWON VDS C2 (VDS1022/I)**
та Android-клієнт, який працює з ним напряму через USB-OTG — без ПК і без офіційного ПЗ.

## Зміст

* 📄 [docs/PROTOCOL.md](docs/PROTOCOL.md) — повна документація протоколу:
  USB-рівень (VID/PID, bulk), формат команд і відповідей, повна карта регістрів (~50),
  профіль VDS1022 (розгортки, дільники, чутливості), формат кадру осцилограми, калібрування
* 📱 `android/` — **VDS C2 Scope**: робочий прототип Android-клієнта (Kotlin)
* 🐍 `tools/vds_query.py` — консольна утиліта перевірки протоколу з ПК (pyusb)

## Джерело даних

Все витягнуто з офіційного ПЗ `OWON_VDS_C2_1.1.7_Setup.exe` (Eclipse RCP, Java):
декомпіляція плагінів `com.owon.vds.foundation` та `com.owon.vds.tiny` (CFR 0.152).
Ключові класи: `CommandTable`, `DeviceAddressTable`, `PackUtil2`, `USBSource`,
`GetDataRunner2`, профіль `VDS1022ONE.txt`.

## Android-клієнт (VDS C2 Scope)

Мінімальний, але робочий клієнт:

* пошук і підключення приладу (VID 0x5345 / PID 0x1234) через `android.hardware.usb`
* ідентифікація приладу (MACHINE_TYPE)
* вибір чутливості каналів (10 кроків, 5 мВ – 5 В/діл) та розгортки (32 кроки, 5 нс – 100 с)
* RUN/STOP, одиночний знімок, осцилограма двох каналів на Canvas
* семпли — сирі 8-бітні коди АЦП (без калібрування; див. §7 PROTOCOL.md)

**Збірка:** відкрий `android/` в Android Studio (gradle sync + Run) або:

```bash
cd android && ./gradlew assembleDebug
# → app/build/outputs/apk/debug/app-debug.apk
```

Вимоги: Android 8.0+ (minSdk 26; перевірено на Xiaomi Mi 9, Android 11),
кабель USB-OTG.

## Статус

* Протокол: задокументовано повністю за винятком калібрувальних таблиць
  (вони індивідуальні для кожного екземпляра приладу і зберігаються у його флеші).
* Клієнт: прототип. Не реалізовано: вимірювання (частота/амплітуда в одиницях),
  калібрування семплів, тригерний рівень (пишеться сире значення), FFT.
