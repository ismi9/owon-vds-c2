# OWON VDS C2 (VDS1022/I) — протокол зв'язку з приладом

Повна документація протоколу USB-обміну портативного осцилографа OWON VDS1022(I) «C2»,
отримана реверс-інжинірингом офіційного ПЗ `OWON_VDS_C2_1.1.7_Setup.exe`
(Eclipse RCP/Java; декомпіляція CFR 0.152 плагінів `com.owon.vds.foundation` + `com.owon.vds.tiny`).

## 1. Фізичний рівень (USB)

| Параметр | Значення |
|---|---|
| VID | `0x5345` (21317) |
| PID | `0x1234` (4660) |
| Клас драйвера | libusb-win32 (bulk-передача) |
| Ендпоінти | Bulk OUT (запис) + Bulk IN (читання), адреси беруться з дескриптора; maxPacketSize визначається автоматично |
| Інтерфейс | interface 0, configuration 1, altsetting 0 |

## 2. Транспортний формат

Усі багатобайтові числа — little-endian.

### Команда (host → прилад)

```
[адреса регістру: u32 LE][кількість байтів значення: u8][значення: N байтів LE]
```

Довжина пакета = 5 + N.

### Відповідь (прилад → host), 5 байтів

```
[код: u8][значення: u32 LE]
```

`код` — ехо-код команди, `значення` — прочитане/підтверджене значення.

### Приклад: запит типу машини

```
запит:   01 40 01 01 56        ; add=0x4001, len=1, value=0x56('V')
відповідь: ?? xx 00 00 00       ; machineCode = u32 LE з байта 1 (>0 = прилад живий)
```

## 3. Ініціалізація

1. Знайти пристрій за VID/PID, відкрити, claim interface.
2. Відправити `MACHINE_TYPE_ADD` (0x4001, len 1, value 86/0x56).
3. Прочитати 5 байтів; `machineCode = u32 LE(байти 1..4)`. Код > 0 → прилад OWON VDS.
4. Опційно: `FPGA_DOWNLOAD_QUERY_ADD` (547/0x223) — перевірити завантаження FPGA.

## 5. Профіль приладу VDS1022 (із `VDS1022ONE.txt` плагіна)

### 5.1 Параметри

```
Канали: 2        АЦП: 100 MSa/s (SAMPLE_100M)
DeepMemory: "5k"  SlowMoveTimebase: "100ms"
ProbeRate (щупи): 1x, 10x, 100x, 1000x
Voltbase (мВ/діл): 5, 10, 20, 50, 100, 200, 500, 1000, 2000, 5000
Timebase (32 кроки): 5ns, 10ns, 20ns, 50ns, 100ns, 200ns, 500ns,
  1us, 2us, 5us, 10us, 20us, 50us, 100ms... до 100s
```

### 5.2 Дільники TIMEBASE (32 значення, індекс = крок розгортки)

```
1, 1, 1, 1, 1, 1, 1, 1, 1, 2, 4, 8, 20, 40, 80, 200, 400, 800,
2000, 4000, 8000, 20000, 40000, 80000, 200000, 400000, 800000,
2000000, 4000000, 8000000, 20000000, 40000000
```

Значення, що записується в `TIMEBASE_ADD` = `SeperateFreq[tb_index]`.
Перед ним приладу надсилається `MULTIFREQ_ADD` (множник частоти).
Кроки ≥ 100 мс працюють у режимі `SLOWMOVE_ADD=1`.

## 6. Читання осцилограми (GETDATA)

1. Сформувати бітову карту каналів `chlflag` (u16): для кожного каналу з останнього
   (CH2) до першого (CH1): `chlflag = (chlflag << 8) | (увімкнений ? 5 : 4)`.
   Обидва канали: `0x0505`.
2. Надіслати `GETDATA_ADD` (0x1000, len 2, value = chlflag).
3. Для кожного УВІМКНЕНОГО каналу прочитати 5211 байтів bulk-IN.
   - Якщо перший байт пакету = `0x45` ('E') → прилад відповів рядком `EBUSY`:
     тригер ще не спрацював, даних нема — повторити запит.
   - Якщо прочитано < 5211 → кадр не готовий.
4. Структура пакету (5211 байт):

```
[0..10]    службовий заголовок, 11 байт
[11..110]  блок даних тригера, 100 байт
[111..5210] блок даних каналу (DM), 5100 байт
```

5. Структура DM-блоку (5100 байт):

```
+0    chl        u8   номер каналу
+1    time_sum   u32  час (для обчислення частоти тригера)
+5    peroid_num u32  кількість періодів (частота = peroid_num / time_sum × шкала)
+9    slow       u16  номер повільного режиму
+11   ...        ADC-семпли, u8 (0..255), центр екрана ≈ зсув +2500
```

Семпли — 8-бітні коди АЦП; перерахунок у вольти виконується за калібрувальними
таблицями (`volt_gain_chX`, `zero_off_chX`, зчитуються з флеша приладу через
`read_flash`).

## 7. Калібрування

Прилад зберігає калібрувальні дані у власній флеш-пам'яті. Доступ:
`read_flash` (0x1B0) → читання блоків → `write_flash` (0x1A0) для запису.
Офіційне ПЗ читає їх при підключенні та застосовує до перерахунку семплів
і рівнів тригера. Сторонній клієнт може використовувати сирі коди АЦП
(центр ~128) без калібрування.
